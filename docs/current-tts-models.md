# Compact local TTS models — verified 2026-10-30

Research only. No engine changes, inference benchmarks, or listening tests were performed. Sources below are model authors, runtime maintainers, their release metadata, and their downloadable artifacts. A repository name, parameter count, advertised speed, or upstream quality grade is not evidence that this app meets its requirements.

## Scope and existing evidence

The target is Apple Silicon, with **M1 / 8 GB / macOS 14+** as the unavailable acceptance machine. This checkout is on M4 / 16 GB. Required p95 actual speech onset is ≤500 ms warm and ≤3 seconds cold; stop to silence ≤100 ms. Initial speech assets must be ≤200 MB, complete installed application ≤500 MB, ready memory ≤500 MB, and active peak ≤1 GB. These are project requirements, not results. Asset MB in this report is decimal; memory figures retain the source's units.

The implemented default remains pinned **Kitten nano v0.1**, through **sherpa-onnx 2.0.1 / ONNX Runtime 1.28.2**, with a locally converted CPU graph. Its manifest totals **36,494,560 bytes**. The eight display names are app aliases for anonymous upstream presets, not verified speaker identities. The optional authentic **Kokoro v1.0 `af_heart`**, native preset **3**, has a **155,030,000-byte** asset manifest at conversion revision `57adb37fc0e8d4bd430cfc1b8f8c2294945b9af2`. The legacy **v1.1-zh does not contain Heart**. These are the task's supplied implementation facts, corroborated where available by the local [Kitten manifest](../resources/kitten-manifest.json), [Heart manifest](../resources/kokoro-heart-manifest.json), and [voice catalog](voices.md).

The [performance report](performance/REPORT.md) contains M4 **software render** measurements of the converted v0.1 default. Its timer excludes selection capture, GPUI, and physical output latency; stop is a software estimate. Harness memory excludes GPUI. It does **not** certify M1, acoustic onset/silence, complete-app cold launch, every voice/speed, or whole-app memory. Heart has not been benchmarked there. None of those results transfers to the candidates below.

### 1. Kitten 0.8: the nearest integration experiment

**Versions and bytes.** Separate the lightweight **model 0.8**, the **Python package 0.8.1**, and the newer, much larger **Kitten-TTS 2**. The latest GitHub release entry is still 0.8.1, whereas current main documents both model families. Neither means that a “Kitten 2” model is a compact 0.8 update. [0.8.1 release](https://github.com/KittenML/KittenTTS/releases/tag/0.8.1), [current family documentation](https://github.com/KittenML/KittenTTS/blob/b9517e3050adced306219f8bea5f117d87ecfaa7/README.md)

The author calls nano **15M** and micro **40M** parameters. At pinned nano-int8 revision `84781d74e29ee25217551556398b42f80593a813`, files are graph **24,369,971 B**, voices **3,278,902 B**, config **688 B**. Micro revision `1ccf72b2c2048fd17efac7de2fab32d10e225084` is graph **41,384,970 B**, voices **3,278,902 B**, config **473 B**: **44,664,345 B** before phonemizer/runtime. Nano fp32 revision `7a1db645b1f3ab9420761d87428e042b9cec3f26` is **60,046,685 B** for those three files. These are useful alternatives for testing quantization and CPU cost, not quality rankings. [Nano int8](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8/tree/84781d74e29ee25217551556398b42f80593a813), [micro](https://huggingface.co/KittenML/kitten-tts-micro-0.8/tree/1ccf72b2c2048fd17efac7de2fab32d10e225084), [nano fp32](https://huggingface.co/KittenML/kitten-tts-nano-0.8-fp32/tree/7a1db645b1f3ab9420761d87428e042b9cec3f26)

The downloaded [sherpa-compatible nano int8 archive](https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/kitten-nano-en-v0_8-int8.tar.bz2) contains a slightly different metadata-bearing graph (**24,370,878 B**), `voices.bin` (**3,276,800 B**), tokens (**1,064 B**), eSpeak data (**17,991,651 B**), license (**11,358 B**), and README (**796 B**). Its computed archive SHA-256 is `6fa5be852612ce761094ba74ee6123b4fc4acfefa79bf64dc63acae4a83af2fd`. The shared `tts-models` release tag is mutable: pin the digest as well as the URL. This inspection verifies bytes, not execution or quality. [Maintainer's example and download link](https://k2-fsa.github.io/sherpa/onnx/tts/all/English/kitten-nano-en-v0_8-int8.html)

**Voices and integration.** English, 24 kHz, eight author-named voices: Bella, Jasper, Luna, Bruno, Rosie, Hugo, Kiki, Leo. These names belong to 0.8's documented mapping; do not rename the current app's v0.1 presets on that basis. The author loader uses length-dependent voice vectors, per-voice speed priors and eSpeak phonemization. Its complete-chunk ONNX inference can be scheduled in short chunks; this is not incremental emission inside one graph call. [Pinned configuration](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8/blob/84781d74e29ee25217551556398b42f80593a813/config.json), [0.8.1 inference code](https://github.com/KittenML/KittenTTS/blob/0.8.1/kittentts/onnx_model.py)

CPU ONNX through the existing C/Rust boundary is the direct route. **sherpa 2.0.1 ignores Kitten `data_dir` and requires caller-provided phoneme codepoints/tokens**; older examples that merely set eSpeak's directory are insufficient for this pinned runtime. The correct frontend, style-vector selection and speed mapping must be checked. No verified Metal/CoreML path for these artifacts is established here. The current default's CPU graph conversion and equivalence checks do not apply automatically to 0.8. [Pinned sherpa API](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.1/sherpa-onnx/c-api/c-api.h), [lightweight model documentation](https://github.com/KittenML/KittenTTS/blob/b9517e3050adced306219f8bea5f117d87ecfaa7/docs/onnx-models.md)

**Licenses and performance.** Code is Apache-2.0; lightweight model cards declare Apache-2.0. The included preset file has no separately identified voice license in the inspected snapshot; underlying speaker/data provenance and distinct voice rights are **not documented there**. eSpeak and frontend dependencies require their own notices/terms. Upstream describes CPU operation, but this research establishes no 0.8 M1/M4 app latency, memory, listening quality, or stop results. [Code license](https://github.com/KittenML/KittenTTS/blob/0.8.1/LICENSE), [model card](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8/blob/84781d74e29ee25217551556398b42f80593a813/README.md)

### 2. Paradee v1.2: the strongest small Heart-derived lead

**Real and newly released.** This is a verifiable author project, with GitHub **v1.2 released October 28**, HF snapshot `ed2934d4df8a4fd891e29584c5e1104649409765`, source, downloadable ONNX files, audio examples and an author paper. The paper describes **v1.0**, not the new four-voice v1.2; do not attribute v1.2's results to the paper. [Release](https://github.com/sahilmahendrakar/paradee/releases/tag/v1.2), [pinned model](https://huggingface.co/sahilmahendrakar/Paradee-8M-v1.2/tree/ed2934d4df8a4fd891e29584c5e1104649409765), [author paper](https://arxiv.org/abs/2610.06817)

**Assets and voices.** The author reports **7.88M parameters**. One int8 graph serves `af_heart`, `bf_isabella`, `am_puck`, `bm_fable`; two American and two British voices, English only, 24 kHz. Voices are embedded, so no Kokoro `voices.bin` or separate vocoder is needed for this graph. The graph plus config is **8,463,946 B**; the optional tokenizer JSON is **3,497 B**, but the reference ONNX loader reads vocabulary from config. [v1.2 architecture and interface](https://github.com/sahilmahendrakar/paradee/blob/v1.2/README.md), [reference loader](https://github.com/sahilmahendrakar/paradee/blob/v1.2/paradee/tts.py)

**Do not call this an 8.5 MB complete text reader.** The reference frontend uses Misaki English with a spaCy small model, US/GB dictionaries and eSpeak fallback. Misaki downloads `en_core_web_sm` when absent; one concrete spaCy 3.8.0 model wheel alone is **12,806,118 B**, before its expanded files or spaCy itself. The app's existing four pinned English dictionary files total **12,625,360 B**; graph + config + those files is **21,089,306 B**, only a known subtotal. An equivalent native frontend may reuse app assets, but compatibility, complete install bytes and memory are **unknown**. Shipping the Python environment is not established to fit the budgets. [Paradee frontend](https://github.com/sahilmahendrakar/paradee/blob/v1.2/paradee/tts.py), [dependencies](https://github.com/sahilmahendrakar/paradee/blob/v1.2/pyproject.toml), [Misaki frontend](https://github.com/hexgrad/misaki/blob/main/misaki/en.py), [spaCy release asset](https://github.com/explosion/spacy-models/releases/tag/en_core_web_sm-3.8.0), [existing dictionary manifest](../resources/kitten-manifest.json)

**Runtime and streaming.** The concrete native route is an ORT CPU session from Rust/C: inputs `input_ids` int64 `[1,T]`, `speed` float32 `[1]`, and v1.2 `voice` int64 `[1]`; output float32 waveform `[1,samples]`. Limit is 512 positions including boundary tokens. The reference wrapper splits sentences and long phoneme sequences, then concatenates completed waveforms; there is no verified within-utterance streaming graph or sherpa adapter here. A caller could schedule small chunks, but first-chunk latency and joins need testing. The author warns that eSpeak phoneme spelling differs from Misaki; a naive frontend swap is not equivalent. Metal/CoreML acceleration is **unverified**. [Interface and frontend warning](https://github.com/sahilmahendrakar/paradee/blob/v1.2/README.md), [chunk implementation](https://github.com/sahilmahendrakar/paradee/blob/v1.2/paradee/tts.py)

**Licenses.** Code/package and model license are Apache-2.0. The author identifies WikiText-103 training sentences as **CC BY-SA 3.0** and Kokoro as teacher. No separate v1.2 voice license is published in the inspected model snapshot; voice identity is learned into the graph. Preserve these distinctions: a model's declared license does not itself document all training-data or speaker permissions, and this report does not infer downstream license compatibility. [Code declaration](https://github.com/sahilmahendrakar/paradee/blob/v1.2/pyproject.toml), [model license](https://huggingface.co/sahilmahendrakar/Paradee-8M-v1.2/blob/ed2934d4df8a4fd891e29584c5e1104649409765/LICENSE), [training-data notice](https://github.com/sahilmahendrakar/paradee/blob/v1.2/README.md#license)

**Reported versus measured here.** The author reports approximately **62× realtime**, one CPU thread on **M4 Pro**, for the newer ONNX head, and v1.2 Heart UTMOS **4.40** versus teacher **4.52** on 200 held-out sentences. UTMOS is a predicted naturalness metric, not a user listening study or speaker-identity test. This app has measured none of those results, and the report supplies neither app p95 speech onset nor M1 cold/stop/memory certification. [Author's runtime/evaluation tables](https://github.com/sahilmahendrakar/paradee/blob/v1.2/README.md)

**Heart limitation.** Distillation from Kokoro's `af_heart` makes Paradee plausibly useful for a smaller **Heart-derived** voice. It does not establish perceptual identity, matching prosody, equivalent pronunciation, or bit-identical Kokoro output. v1.2 changes the audio head and shares weights across four voices. Label any evaluation preset “Heart (Paradee)” or “Heart-derived” until blinded listening and speaker-similarity checks support a stronger claim; retain authentic Kokoro v1.0 as the reference. [Author's training and v1.2 description](https://github.com/sahilmahendrakar/paradee/blob/v1.2/README.md)

### 4. Kokoro v1.0: authentic Heart control

**Artifacts and voices.** Original v1.0 is dated January 27, 2025, **82M parameters**. The selected runtime conversion has graph **114,202,993 B**, `voices.bin` **28,200,960 B**, tokens **687 B**. Those total **142,404,640 B**; four app dictionaries add **12,625,360 B**, giving **155,030,000 B**. The repository's Apache license is another **11,358 B** if newly downloaded; it is not in that speech-download sum. The maintainer explicitly generated the 54-voice table from official v1.0 styles, including `af_heart`. English offers 20 American and eight British voices in the author's inventory. [Original card](https://huggingface.co/hexgrad/Kokoro-82M/blob/f3ff3571791e39611d31c381e3a41a3af07b4987/README.md), [conversion files](https://huggingface.co/csukuangfj/kokoro-int8-multi-lang-v1_0/tree/57adb37fc0e8d4bd430cfc1b8f8c2294945b9af2), [conversion explanation](https://huggingface.co/csukuangfj/kokoro-int8-multi-lang-v1_0/blob/57adb37fc0e8d4bd430cfc1b8f8c2294945b9af2/README.md), [voice inventory](https://huggingface.co/hexgrad/Kokoro-82M/blob/f3ff3571791e39611d31c381e3a41a3af07b4987/VOICES.md)

**Integration and limits.** This is the existing optional CPU ONNX/sherpa path. Sentence/phoneme chunk scheduling is possible; it does not make a full-waveform graph an incremental acoustic decoder. The author warns that very short utterances can be weak and long utterances can rush. This matters when shrinking the first chunk for startup speed. Metal/CoreML on the selected int8 artifact is unverified. Smaller voice-table packaging could reduce bytes while retaining the original graph/style, but no reduced bundle was constructed or validated here. [Author's duration warnings](https://huggingface.co/hexgrad/Kokoro-82M/blob/f3ff3571791e39611d31c381e3a41a3af07b4987/VOICES.md), [sherpa interface](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.1/sherpa-onnx/c-api/c-api.h)

## Evaluation and truthful voice indicators

Measure candidates using the same selected text, output path, hardware, OS, runtime build, thread count, chunk policy and speed. Pin every graph, frontend, tokenizer, style table and seed policy. Record raw trials, failures and p50/p95/worst; randomize/interleave candidates and report load/thermal conditions. Sample each offered voice and supported speed. CPU timing must include normalization/phonemization and queueing, not just `session.run`; distinguish generated first chunk, rendered first speech, and actual audible output. Measure whole-app ready/active memory and complete installed bytes. An M4 run is a development comparison; M1 / 8 GB / macOS 14+ remains a separate acceptance gate.

Cold tests must name their conditions: unloaded graph, fresh process, full app launch and cold filesystem caches are different experiments. For the actual product gate, include selection capture, GPUI, audio-device setup and physical onset. For stop, measure request-to-physical-silence while generation and playback are active; suppressing output and cancelling inference are separate behaviors. A fast RTF or an upstream first-chunk claim proves none of these targets.

For the UI:

- Do not turn Kokoro's upstream training-data grades into app-tested quality scores, stars or percentages. If provenance is shown at all, call it **“Upstream grade”**, explain its meaning outside the main picker, and link its source. [Grade definitions](https://huggingface.co/hexgrad/Kokoro-82M/blob/f3ff3571791e39611d31c381e3a41a3af07b4987/VOICES.md)
- Do not translate UTMOS into “quality 4.4/5” or claim a distilled voice is indistinguishable from its teacher. Quality, intelligibility, speaker resemblance and sentence joins need separate evidence.
- Show a speed/latency indicator only after matched CPU sampling on the stated device/runtime/input policy. An upstream model-wide number must not become a per-voice result. Use **“Not measured”** or omit an indicator when evidence is absent.
- Prefer functional facts: **English**, **American/British** only when supported by the relevant model, **Download · N MB**, **Ready**, **Downloading**, and a preview button. Show engine/version where needed to distinguish authentic **Heart (Kokoro)** from **Heart (Paradee)**. Keep aliases distinct from source identity and keep accessible names.

## Ranked evaluation shortlist

1. **Kitten 0.8 micro and nano int8, with nano fp32 as a diagnostic control.** Lowest integration distance, eight voices, concrete compact exports. First prove frontend/style/speed parity through the pinned runtime, then compare against the optimized v0.1 default. No default change is justified yet.
2. **Paradee v1.2.** Highest-priority experiment for a much smaller Heart-derived option with four voices. Prove a complete native frontend and test Heart resemblance/intelligibility against authentic Kokoro before giving it an identity or quality claim.
3. **Pocket `english_7m_2026-10` and `english_18m_2026-10`, runtime v4.0.1.** Strongest verified recent incremental-streaming/Rust path. Start with the four appropriately licensed voice states above; measure cold/ready memory, cancellation and macOS 14 behavior. Evaluate `_refl` separately; keep experimental 2M behind those until quality is established.
4. **Authentic Kokoro v1.0 int8 as the Heart control and existing optional-engine evaluation.** Its known complete speech manifest fits the asset budget; measure the actual graph/voice/chunk combination before attaching speed or quality indicators.
5. **Kokoro-7M-Distill only as a research comparison.** Compact checkpoint, but one supported voice, no verified native export, and an explicit warning against using Heart styles. It does not satisfy the current voice catalog requirement.
6. **Defer Supertonic 3 for this budget.** The official archived assets exceed initial-download limits and upstream peak-memory evidence is unfavorable. Reconsider only with a concrete, licensed, smaller complete package and new measurements.
