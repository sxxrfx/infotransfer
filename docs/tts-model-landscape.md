# Open TTS model landscape — 2026-10-30

This is a catalog of **44 relevant model/engine families**, including current successors, compact local options, expressive speech generators, multilingual research models, and classic synthesizers. It is broad, not literally exhaustive: no registry can guarantee every language checkpoint, fine-tune, distillation, conversion, or new derivative. A downloadable checkpoint is not automatically open source or commercially usable.

Research used author repositories, author Hugging Face cards and file metadata, original papers, and license texts, checked on **October 30, 2026**. Only documentation and metadata were fetched; no model weights were downloaded or run, and no user text was submitted to a speech service. [The earlier compact-model notes](current-tts-models.md) were leads, not authority. Version-sensitive claims below were rechecked upstream.

## What matters for InfoTransfer

The target is **M1 / 8 GB**, with **≤200 MB initial speech assets, ≤500 MB complete installed app, ≤500 MB ready memory, and ≤1 GB active peak**. The original fast-model references are ≤500 ms warm speech onset and ≤3 seconds cold. The user now permits longer speech-start latency for higher-quality options; no new numerical budget has been selected. Visual feedback and ≤100 ms stop-to-silence remain separate responsiveness requirements. Storage and RAM limits have not been relaxed. These are targets, not results for any candidate here. Asset MB means decimal MB; a parameter count is not a download size or memory measurement.

The most relevant small experiments are **Kitten 0.8, Paradee 1.2, authentic Kokoro v1.0 int8, Pocket's October 7M/18M variants, and Phonon 31M**. The latter two offer actual incremental audio paths. None is certified here against the complete M1 app budgets. Piper and classic engines are alternatives when their voice and code terms fit. Broad instruction-based emotional performance usually belongs to a much larger package; smaller exceptions and nonverbal controls exist, but no fully measured fitting emotional/cloning package was established in this research.

The existing [voice screening](performance/voice-evaluation/REPORT.md) has **21 voices / 294 recordings**, but the production native frontend skips unsupported words, while experimental models used different author frontends. Those scores cannot establish the intrinsic quality ranking of Kokoro, Kitten, and Paradee. Fix the frontend and compare equivalent pipelines before choosing a family from those results.

### Reading the catalog

| Label | Meaning |
| --- | --- |
| **P** | Author declares permissive licenses for the selected code **and** main weights, such as Apache-2.0/MIT. This does not clear every dependency, recording, speaker, or dataset. |
| **A** | Open weights with attribution terms, such as CC BY 4.0; separately examine access conditions and voice assets. |
| **C** | Open-source copyleft engine/code; commercial use is not inherently prohibited, but redistribution/linking obligations differ from permissive code. |
| **R** | Noncommercial, research-only, use-restricted, or custom community model terms. Do not describe these as uniformly permissive open-source models. |
| **?** | Important terms or complete component permissions remain unverified or conflict with supplementary wording. |
| **Candidate** | Concrete small assets and a CPU/native route make testing worthwhile. This is **not** a pass on install size, memory, latency, or quality. |
| **Outside** | The inspected stock artifacts already exceed an asset limit, or the documented stack is plainly beyond the target. A new conversion needs a fresh assessment. |
| **Unproven** | There is no complete, version-specific fitting package established here. |

An `Outside` model may still run on an 8 GB Mac with a port or quantization. That does not make it fit a 500 MB app or 1 GB peak. Quantization can change pronunciation, stability, and backend compatibility; a community conversion inherits the source model's terms.

## What “emotion and advanced features” actually means

| Capability | What it provides | Important distinction |
| --- | --- | --- |
| Explicit emotion/style instructions | A description, tag, or emotion vector steers delivery. | Model/version-specific: Qwen 1.7B CustomVoice, CosyVoice3, IndexTTS2/2.5, VoxCPM2, Kitten-TTS 2, Fish S2/Drama 3. An arbitrary `[happy]` string is not a universal API. |
| Nonverbal events | Laughter, breaths, coughs, sighs, crying, etc. | Chatterbox Turbo/Nano, Bark, Dia, Supertonic3 and other listed models have particular documented cues. A laugh tag is not a continuous emotion control. |
| Reference prosody/style | Inherits rhythm, tone, accent, or performance from audio. | F5, XTTS, StyleTTS2, OpenVoice pipelines and cloning models offer different forms. Cloning identity does not imply independently adjustable emotion. |
| Voice cloning / voice design | Reuses a reference identity / creates a voice from attributes. | Different capabilities. A model with fixed presets or precomputed voice states may not expose arbitrary local cloning. |
| Joint multi-speaker dialogue | Speaker turns share conversational acoustic context. | Dia, FireRedTTS2, full VibeVoice, Fish and MOSS dialogue variants differ from concatenating independent single-speaker calls. |
| Streaming | Audio can arrive before the whole utterance finishes; some models also accept unfinished text. | Audio-output streaming, text-input streaming, and sentence chunking are three different things. Streaming architecture does not guarantee that a particular CLI/server exposes it. |
| Pronunciation / timing controls | Phonemes, dictionaries, pauses, speed, or duration. | **SSML belongs to the engine/frontend integration**, not automatically to the neural weights. Pitch/speed post-processing is not learned emotion. Exact duration claims must match released code. |

The catalog below is the evidence for these distinctions. “Not documented” means no supported control was established in the inspected upstream release; it does not claim that the architecture could never learn it.

## Compact and local-first families

### 1. KittenTTS: lightweight 0.8 versus Kitten-TTS 2

- **License/size:** **P for lightweight 0.8:** Apache-2.0 code and model cards. Nano is advertised as 15M, micro 40M, mini 80M. Nano-int8 graph + eight-voice file + config is **27,649,561 B**; frontend/runtime are additional. **R for Kitten-TTS 2:** code badge remains Apache, but weights use the **Stellon Labs Community License**. This is a different **1.7B** speech LM; its compressed `emb4` LM alone is **492,114,403 B**, before decoder/tokenizer. [0.8 documentation](https://github.com/KittenML/KittenTTS/blob/main/docs/onnx-models.md), [nano snapshot](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8/tree/84781d74e29ee25217551556398b42f80593a813), [2 weights/license](https://huggingface.co/KittenML/kitten-tts-2/tree/c93cb7c271baa51d9ae8204d5277988906f235a2).
- **Features/tradeoffs/fit:** 0.8 is English, eight fixed voices, speed control, CPU ONNX; no documented cloning, emotion instructions, or within-call audio streaming. It is a **Candidate**, but needs its correct phonemizer and voice-vector selection. Version 2 adds 20 languages, 115 presets, cloning, emotion/event/emphasis tags, and sentence chunking; official CPU/C++ and Mac/MLX paths exist. Its documented roughly 6 GB CPU RAM / 2 GB model-and-decoder setup is **Outside**. Do not transfer v2 features to the small model. [Current family guide](https://github.com/KittenML/KittenTTS), [code license](https://github.com/KittenML/KittenTTS/blob/main/LICENSE).

### 2. Kokoro 82M v1.0, with a separate 7M distillation

- **License/size:** **P**, Apache-2.0 author code and v1.0 weights; **82M**. Original checkpoint is **327,212,226 B**. A pinned runtime-maintainer int8 conversion has graph + 54-voice table + tokens **142,404,640 B**; with the app's four English dictionaries the known asset total is **155,030,000 B**. [Author card](https://huggingface.co/hexgrad/Kokoro-82M/blob/f3ff3571791e39611d31c381e3a41a3af07b4987/README.md), [code](https://github.com/hexgrad/kokoro), [conversion](https://huggingface.co/csukuangfj/kokoro-int8-multi-lang-v1_0/tree/57adb37fc0e8d4bd430cfc1b8f8c2294945b9af2).
- **Features/tradeoffs/fit:** Multiple language/voice presets, speed and style-vector mixing; **no official zero-shot cloning or semantic emotion-tag API**. Chunked pipeline output is not within-graph streaming. Authentic `af_heart` is in v1.0; do not substitute a different revision's voice table. A **Candidate** with mature CPU ONNX routes, but correct text normalization/G2P and app latency remain material. **Kokoro-7M-Distill** is a separate community checkpoint (~30.62 MB with its `af_msa` style/config), Apache-declared weights, patched Python path, unverified complete code/package terms; it is **not Heart** and not an established native drop-in. [Voice inventory](https://huggingface.co/hexgrad/Kokoro-82M/blob/f3ff3571791e39611d31c381e3a41a3af07b4987/VOICES.md), [distillation](https://huggingface.co/oddadmix/Kokoro-7M-Distill/tree/9357717e6499717b769ab65de61797aa7c501c86).

### 3. Paradee 8M v1.2

- **License/size:** **P**, Apache-2.0 code/model; **7.88M**, English. October 28 v1.2 int8 graph + config: **8,463,946 B**, with four embedded presets. This excludes Misaki dictionaries, spaCy/eSpeak fallback where used, runtime, and app. Training text is identified as WikiText-103, CC BY-SA 3.0; that is separate from the declared model license. [v1.2 source](https://github.com/sahilmahendrakar/paradee/tree/v1.2), [pinned assets/license](https://huggingface.co/sahilmahendrakar/Paradee-8M-v1.2/tree/ed2934d4df8a4fd891e29584c5e1104649409765).
- **Features/tradeoffs/fit:** Speed, US/UK pronunciation, `af_heart`, `am_puck`, `bf_isabella`, `bm_fable`; **no cloning/emotion API**, sentence/phoneme chunking rather than incremental graph emission. A strong size-based **Candidate** for native ORT CPU. New release, new adapter needed, and the author warns that eSpeak phonemes are not interchangeable with training's Misaki frontend. Heart is **teacher-derived**, not proven perceptually identical. The linked paper describes v1.0, not all v1.2 behavior; author M4 Pro speed/UTMOS claims are not InfoTransfer/M1 results. [Interface and evaluation distinctions](https://github.com/sahilmahendrakar/paradee/blob/v1.2/README.md).

### 4. Pocket TTS, especially October 2026 small models

- **License/size:** **A/?**, code **MIT**, model metadata **CC BY 4.0**, cloning repository gated with additional access/use wording. Runtime **v4.0.1** follows October 20's 18.2M, 6.9M, and experimental 1.9M English models, including `_refl` reward-finetuned variants. Selected checkpoint/tokenizer/config plus four states (`alba`, `javert`, `marius`, `peter_yearsley`) total about **126.64 / 70.27 / 48.64 MB** respectively; package/libraries excluded. [Release](https://github.com/kyutai-labs/pocket-tts/releases/tag/v4.0.1), [configs](https://github.com/kyutai-labs/pocket-tts/tree/v4.0.1/pocket_tts/config), [model metadata](https://huggingface.co/api/models/kyutai/pocket-tts?blobs=true), [public fallback files](https://huggingface.co/kyutai/pocket-tts-without-voice-cloning/tree/a7056f505a4a8ca72d8b5fb1440071d6f1a35739).
- **Features/tradeoffs/fit:** Incremental 24 kHz audio, reference-conditioned voices/cloning in the appropriate model, CPU operation, official standalone **Rust** runtime. The larger family has seven documented languages, but the new tiny checkpoints are English. No independently parameterized emotion control established. **7M/18M are Candidates**; new architectures and checkpoint-specific voice states need evaluation, and 2M is experimental. Preset recordings differ: Alba/VCTK **CC BY**, donations/Voice-Zero **CC0**, Expresso/EARS **CC BY-NC**. Cosette/Jean must not be silently treated like permissive defaults. [v4.0.1 guide](https://github.com/kyutai-labs/pocket-tts/blob/v4.0.1/README.md), [voice-license inventory](https://huggingface.co/kyutai/tts-voices).

### 5. Gradium Phonon 31M / 40M

- **License/size:** **P for `phonon-31m-en`**: Apache-2.0 weights, tokenizer, bundled voice; runtime **MIT OR Apache-2.0**. **R for 40M siblings**, including multilingual: gated **CC BY-NC 4.0**. The 31M count excludes the audio tokenizer; HF tensor metadata totals ~41.1M. Official q8 GGUF is **64,512,352 B**; q8 + `config.json` + `tokenizer.model` + default voice is a **64,838,167 B subtotal**, not the complete installed app. [Pinned 31M files](https://huggingface.co/gradium/phonon-31m-en/tree/92741c5b07d085ff840e26fea8ce43110b87852f), [author model card](https://huggingface.co/gradium/phonon-31m-en), [40M terms](https://huggingface.co/gradium/phonon-40m-en).
- **Features/tradeoffs/fit:** Frame-by-frame streaming, voice states, rate conditioning; Rust/C FFI and Apple Core ML/Swift routes make 31M an important **Candidate**. English-only 31M versus five-language 40M choices is a real license/coverage tradeoff. Studio-based cloning/design and runtime voice tools are not proof that the model bundle includes an arbitrary local raw-audio cloner or emotion API. Extra catalog voices need their own terms. Upstream M5/iPhone measurements cannot certify M1 whole-app memory or onset. [Runtime/platform and voice workflow](https://github.com/gradium-ai/xn-ptts), [Rust package terms](https://github.com/gradium-ai/xn-ptts/blob/main/ptts/README.md).

### 6. Piper / OHF Piper 1

- **License/size:** **C/?**. Maintained **`OHF-Voice/piper1-gpl` is GPL-3.0**, unlike the old MIT `rhasspy/piper` code. Voice weights/datasets have **per-voice cards**; the voice repository's MIT badge is not a blanket grant for every speaker. Representative `en_US-lessac-medium` ONNX is about **63.2 MB**, before config/eSpeak/runtime; other voices differ. [Current engine](https://github.com/OHF-Voice/piper1-gpl), [GPL](https://github.com/OHF-Voice/piper1-gpl/blob/main/COPYING), [voice repository](https://huggingface.co/rhasspy/piper-voices), [Lessac-specific card](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/lessac/medium/MODEL_CARD).
- **Features/tradeoffs/fit:** Local CPU ONNX, many language-specific voices, some multi-speaker checkpoints, speed/noise/prosody controls. Sentence-by-sentence PCM can be consumed progressively; ordinary models are not text-in bi-streaming dialogue LMs. No universal cloning/emotion tags. A **Candidate** for a small, predictable reader with mature C/C++ integration; language/voice consistency varies and each extra model adds assets. Copyleft and speaker-specific terms must fit the actual distribution. The project currently asks for maintainers. [Voice selection guidance](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/VOICES.md).

### 7. Supertonic 1 / 2 / 3

- **License/size:** **R**, **MIT sample code / OpenRAIL-M weights**, with use restrictions. V3 is ~99M, 31 languages, ten fixed presets, 44.1 kHz. Its four ONNX graphs total **398,075,273 B**; configs/indexer/settings/all presets bring the known inference-data total to **401,276,918 B**. V2's corresponding data is ~267.30 MB. Both exceed 200 MB initial assets. [Archived author guide](https://github.com/supertone-oss-archive/supertonic), [v3 snapshot/license](https://huggingface.co/supertone-oss-archive/supertonic-3/tree/aafc6e32416a594460b32413efc49d7fe4ce6d46), [v2 snapshot](https://huggingface.co/supertone-oss-archive/supertonic-2/tree/7edbcd0bba8cd579100a353a9e0b2b49cad7c875).
- **Features/tradeoffs/fit:** Cross-platform ONNX, speed/denoising controls; current v3 documentation lists **ten expression/event tags**, including laugh/breath/sigh. This is more than v2, but **the public release does not include an official local voice-cloning pipeline**; hosted service showcases must not fill that gap. Native language bindings are useful, but stock assets are **Outside**. The original project is archived without further support. Do not call its model MIT or promise the former Voice Builder service remains available. [Author's release/interface/service distinctions](https://github.com/supertone-oss-archive/supertonic/blob/main/README.md).

### 8. NeuTTS Air / Nano / multilingual Nano / 2E

- **License/size:** **R for the current repository/bundle.** Air **weights** declare Apache-2.0; Nano/2E weights use **NeuTTS Open License 1.0**, and the current code repository's root `LICENSE` also uses that custom license. Do not infer Apache code from the Air weight card. Counts distinguish active from embeddings: Air ~360M/~552M, Nano ~120M/~229M, 2E ~125M/~236M. Nano Q4 is **194,600,640 B**, but the official int8 ONNX decoder adds **312,292,102 B**: **506,892,742 B before references/runtime**. 2E Q4 alone is **300,693,920 B**. [Author variant table](https://github.com/neuphonic/neutts), [current repository license](https://github.com/neuphonic/neutts/blob/main/LICENSE), [Air metadata](https://huggingface.co/neuphonic/neutts-air), [Nano files](https://huggingface.co/neuphonic/neutts-nano-q4-gguf/tree/d775fb6ff95c60a076c68994d9f084473ad9fb86), [decoder](https://huggingface.co/neuphonic/neucodec-onnx-decoder-int8/tree/d4b449d34211ffe3b5efc57fa464b37393f8ce7f), [2E files/terms](https://huggingface.co/neuphonic/neutts-2e-q4-gguf/tree/021bd72d8eeff6f548e5c9209d03db6b6dff4939).
- **Features/tradeoffs/fit:** Air/Nano clone voices; GGUF path streams. Language-specific Nano models cover EN/DE/FR/ES. **2E is English with four fixed speakers and six emotions plus neutral**, rather than an arbitrary emotional clone API. Accelerate/CPU Mac instructions are concrete, but the inspected packages are **Outside**; alternative smaller codec pairings remain unproven. Upstream `llama-bench` tokens/sec excludes the codec and is not end-to-end speech latency. [Inference/emotion guide](https://github.com/neuphonic/neutts/blob/main/README.md).

## Larger families with permissive code and weight declarations

These can be valuable when feature scope changes, but their stock packages generally exceed InfoTransfer's limits. Where supplementary use wording or dependencies complicate a permissive declaration, it is called out rather than treated as clearance.

### 9. Qwen3-TTS 12Hz, 0.6B / 1.7B

**P — Apache-2.0 code, released models and tokenizer.** Ten languages. **1.7B CustomVoice** provides nine preset voices with instruction-based delivery/emotion; **1.7B VoiceDesign** creates voices from descriptions; **Base 0.6B/1.7B** provides reference cloning. The release table does **not** grant instruction control to Base or 0.6B CustomVoice. Streaming architecture is documented, but the example/runtime path must actually expose it. Pros: clear task-specific variants, multilingual clone/design and control. Cons: multiple checkpoint roles, stochastic control, large tokenizer/component package. **Outside**: even 0.6B Base has **1.829 GB main weights + 682 MB speech tokenizer**, not a 0.6 GB bundle. [Author variant table/code](https://github.com/QwenLM/Qwen3-TTS), [0.6B pinned files](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base/tree/5d83992436eae1d760afd27aff78a71d676296fc), [technical report/license statement](https://arxiv.org/abs/2601.15621). No newer released Qwen TTS successor was verified beyond this family; Qwen ASR/Omni is not the same product.

### 10. Chatterbox original / Turbo / Nano / Multilingual V3

**P — MIT code and inspected weight cards.** Original English/multilingual models are advertised as 500M; **Turbo 350M**, **Nano 110M**, both English; latest multilingual **V3** and single-language packs are separately identified. Original has CFG/exaggeration controls; Turbo/Nano have a single-step acoustic decoder and native nonverbal tags such as cough/laugh/chuckle. Reference cloning and output watermarking are documented. Pros: useful public inference API, cloning, explicit event support, CPU/MPS options. Cons: exaggeration is not arbitrary semantic emotion selection; do not assume every variant supports every control or streaming server. **Outside** stock assets: Nano's T3 file is **869.90 MB** and its mean-flow decoder **1,064.88 MB**, before other components. “110M” is not complete bundle size. [Current model zoo](https://github.com/resemble-ai/chatterbox), [Nano card/files](https://huggingface.co/ResembleAI/chatterbox-nano/tree/71ccd1d0081b430592cea481f4307e764e07bc64), [Turbo files](https://huggingface.co/ResembleAI/chatterbox-turbo/tree/749d1c1a46eb10492095d68fbcf55691ccf137cd).

### 11. CosyVoice 1 / 2 / Fun-CosyVoice3

**P — Apache-2.0 code and selected `Fun-CosyVoice3-0.5B-2512` card.** Older 300M variants distinguish base/SFT/Instruct; 2 and 3 use 0.5B-class backbones. V3 provides nine common languages, Chinese dialects, cross-language cloning, instructions for emotion/speed/volume, phoneme pronunciation repair, and **text-in/audio-out bi-streaming**. Pros: broad deploy/train stack and unusually useful pronunciation controls. Cons: tokenizer, flow, vocoder, speaker model and optional frontend assets substantially exceed the headline LM; GPU-serving timings are not Mac timings. **Outside**: `llm.pt` alone is **2.025 GB**, with a ~1.329 GB flow checkpoint and other components. Choose base versus RL weights explicitly. [Current author guide](https://github.com/QwenAudio/CosyVoice), [pinned v3 files/card](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512/tree/29e01c4e8d000f4bcd70751be16fa94bf3d85a18).

### 12. Dia 1.6B / Dia2 1B and 2B

**P with supplementary use wording — Apache-2.0 code/model declarations.** Dia generates English two-speaker scripts with audio conditioning and nonverbal events. **Dia2** accepts partial text, uses speaker-specific audio prefixes, and documents streaming architecture with ~two-minute context. Pros: conversational co-generation rather than independently stitched voices; reference tone and speaker conditioning. Cons: identities vary without prefixes; short/long-script constraints, codec and optional Whisper prefix transcription add cost. Dia2's README still lists a real-streaming server as upcoming, so architecture support is not proof of a ready server interface. **Outside**: billion-parameter model + codec; no fitting M1 package established. Use the release-specific supported event syntax; do not transfer Dia's full event list untested to Dia2. [Dia](https://github.com/nari-labs/dia), [Dia2](https://github.com/nari-labs/dia2), [Dia2 weights/card](https://huggingface.co/nari-labs/Dia2-1B).

### 13. VibeVoice long-form / Realtime 0.5B

**P declarations / supplementary research-use wording — MIT code and inspected TTS weight cards.** Full **1.5B** TTS supports long-form dialogue, up to four speakers and author-stated 90-minute generation. **Realtime 0.5B** is a different **single-speaker**, embedded-voice-prompt path, primarily English; experimental language/style voices do not establish equal multilingual support. Pros: long-form context and a separate low-latency design. Cons: full versus realtime features are not interchangeable; no verified general emotion-instruction API or arbitrary raw-reference cloner for Realtime. Its docs also retain an unfinished text-input streaming checklist item; validate the actual integration. **Outside**: Realtime weights **2.035 GB**, full 1.5B release ~5.408 GB across three shards. Recent VibeVoice ASR/BitNet releases are **recognition**, not smaller TTS successors. [Family](https://github.com/microsoft/VibeVoice), [Realtime guide](https://github.com/microsoft/VibeVoice/blob/main/docs/vibevoice-realtime-0.5b.md), [Realtime files](https://huggingface.co/microsoft/VibeVoice-Realtime-0.5B/tree/6bce5f06044837fe6d2c5d7a71a84f0416bd57e4), [full TTS files](https://huggingface.co/microsoft/VibeVoice-1.5B/tree/c00898d257e6b46004e3e2866a47534085fb685a).

### 14. GLM-TTS

**P declarations — Apache-2.0 code / MIT model card**, rather than one license inferred for both. A 1.5B-class TTS system, mainly Chinese and mixed English, with 3–10-second cloning, streaming flow inference, and hybrid phoneme/text pronunciation repair. Pros: targeted pronunciation control and public RL training machinery. Cons: **the README still marks RL-optimized weights as coming soon**; emotion/laughter reward research does not establish a shipped arbitrary emotion selector or all paper improvements in the downloadable base. **Outside**: LLM shards total **6.208 GB**, plus flow/vocoder/tokenizer. CPU/Mac adaptations would be separate work, not evidence of budget fit. [Author release status](https://github.com/zai-org/GLM-TTS), [code license](https://github.com/zai-org/GLM-TTS/blob/main/LICENSE), [pinned model files/card](https://huggingface.co/zai-org/GLM-TTS/tree/b3feb691fa4cf590eec4418f6275f95220e58844).

### 15. OpenVoice V1 / V2, usually with MeloTTS

**P — MIT code and V1/V2 release declaration; V2 HF card MIT.** A tone-color conversion/cloning pipeline, not a single self-contained text model. It preserves/controls style through a base synthesizer, with native V2 support for EN/ES/FR/ZH/JA/KO; V1 examples expose emotion/accent/rhythm controls. Pros: separates identity from base delivery, cross-language conversion, CPU-capable components. Cons: controls and quality depend on the base model; **MeloTTS's standard V2 pairing is not a universal emotion-instruction model**, and converter speed is not complete TTS speed. **Outside** the inspected stock pairing: converter **131.32 MB** plus English Melo checkpoint **207.86 MB**, before its text encoder/frontends/runtime. Other selected bases need separate accounting. [OpenVoice author guide](https://github.com/myshell-ai/OpenVoice), [V2 files](https://huggingface.co/myshell-ai/OpenVoiceV2/tree/f36e7edfe1684461a8343844af60babc2efbb727), [MeloTTS](https://github.com/myshell-ai/MeloTTS), [English base files](https://huggingface.co/myshell-ai/MeloTTS-English/tree/bb4fb7346d566d277ba8c8c7dbfdf6786139b8ef).

### 16. VoxCPM 0.5B / 1.5 / VoxCPM2

**P — Apache-2.0 code and weights.** Original is 0.5B; 1.5 is 0.6B; April 2026 **VoxCPM2** is a 2B backbone with 30 languages and 48 kHz output. V2 adds natural-language voice design and style-guided cloning, while transcript-plus-reference continuation preserves detailed delivery. Audio streaming and LoRA/fine-tuning are documented. Pros: identity and delivery can be steered separately in v2, with a public continuous-audio architecture. Cons: v1/1.5 do not inherit all v2 features; full tensor count/package is larger than backbone count. **Outside**: v2 main weights **4.580 GB** + AudioVAE **376.95 MB**. Official docs link community CPU/Metal GGUF paths and MPS handling; those do not make the package fit our app. [Author variants/controls](https://github.com/OpenBMB/VoxCPM), [pinned v2 files](https://huggingface.co/openbmb/VoxCPM2/tree/32279effe8c19989596f05d353d1447f51d9e915).

### 17. MOSS-TTS family, including Nano

**P declarations — Apache-2.0 code and inspected Nano/codec/v1.5 weight metadata.** Distinct tasks: **8B v1.5** long-form TTS, **4B Local Transformer v1.5**, **1.7B Realtime**, **TTSD** dialogue, **VoiceGenerator** design; SoundEffect is audio generation, not a smaller reader. Latest guides document 31-language v1.5 and explicit pauses. **Nano** is ~100M plus ~20M audio tokenizer, reference cloning, incremental output, 48 kHz stereo, and a CPU/ONNX path. Pros: Nano is a useful multilingual local lead; separate dialogue/design paths. Cons: do not transfer all flagship controls to Nano; complete assets matter. **Outside stock initial assets**: Nano **234,693,095 B** + codec **87,922,568 B** = **322,615,663 B** before text/config/runtime. A smaller complete export remains **Unproven**. ## Biggest license and feature traps

1. **Code license ≠ weights ≠ voice recordings ≠ training data.** F5 is MIT/NC; Spark's current weights are **NC-SA**, despite Apache code; XTTS is MPL library/CPML weights; Supertonic is MIT/OpenRAIL-M; ChatTTS is AGPL/NC; OmniVoice is Apache/NC. The linked exact cards above govern those distinctions. None of those badges alone proves speaker rights.
2. **Family upgrades can change terms completely.** Kitten 0.8 is Apache; Kitten-TTS 2 requires commercial registration, with separate-license triggers above **US$1M annual revenue or cumulative funding**, subject to affiliate/end-product provisions. NeuTTS Air **weights** are Apache; Nano/2E and the current repository root license use a **US$5M revenue-threshold** custom license. Phonon 31M is Apache; 40M models are **NC**. [Kitten 2 license](https://huggingface.co/KittenML/kitten-tts-2/blob/c93cb7c271baa51d9ae8204d5277988906f235a2/LICENSE.md), [NeuTTS repository license](https://github.com/neuphonic/neutts/blob/main/LICENSE), [NeuTTS 2E license](https://huggingface.co/neuphonic/neutts-2e-q4-gguf/blob/021bd72d8eeff6f548e5c9209d03db6b6dff4939/LICENSE), [Phonon author inventory](https://huggingface.co/gradium/phonon-31m-en).
3. **Fish S2-Pro is not Drama 3's commercial grant.** S2 remains research/noncommercial. Drama's October 13 community license allows some commercial use below **US$500,000 aggregate annual revenue**, with affiliate/downstream rules; **hosted speech-generation services require a separate license regardless of revenue or purpose**. It also has attribution/display and use conditions. Do not call Drama Apache or assume “free startup use” authorizes a hosted API. [Exact Drama terms](https://huggingface.co/fishaudio/drama-3/blob/78e5ab79e49aa9a25abe8799eff2c4d73a1c3216/LICENSE).
4. **IndexTTS is not simply NC or unrestricted OSS.** Its bilibili license has usage/downstream obligations, limits on improving other models, and separate-license triggers for **>100M monthly active users or >RMB1B prior-year annual revenue**. **Higgs v3** is separately noncommercial. **Dramabox** is LTX-2 community licensed, with a paid-license trigger at **US$10M annual revenue**, competition/use restrictions, and separate encoder terms. [Index terms](https://github.com/index-tts/index-tts/blob/main/LICENSE), [Higgs v3 terms](https://huggingface.co/bosonai/higgs-audio-v3-tts-4b/blob/239f63fb7b02b1aa085f98d9efae5e35cc5523e8/LICENSE), [Dramabox terms](https://huggingface.co/ResembleAI/Dramabox/blob/404f967f653fa1170dc15a9d1ddd3fdb9a0a842d/LICENSE).
5. **Voice presets are not separate models.** Eight Kitten presets share one model; Paradee embeds four learned voices; Heart in Kokoro is a style preset. A Heart-derived distilled model is not an identity-equivalent replacement. Pocket state compatibility and recording licenses follow the exact checkpoint/source voice, not just a friendly display name.
6. **Cloning is not independent emotion control.** Qwen Base clones but its release table does not offer the 1.7B instruction interface. XTTS/F5 reference delivery is not a universal emotion parameter. NeuTTS **2E** has emotional **fixed speakers**; Nano's cloning path does not acquire those controls by association. ChatTTS's released control tokens are much narrower than its research ambitions.
7. **Paper, API and roadmap features are not shipped local features.** GLM RL weights are still listed as forthcoming; Index2 exact duration control was not enabled; Dia2's real-streaming server is upcoming; Voxtral TTS3/API S2.1 features do not establish matching public weights. Supertonic's hosted cloning demos do not supply an official local cloner. Keep capability flags at model-version-runtime level.
8. **Small backbone ≠ small system.** Chatterbox Nano, NeuTTS Nano, MOSS Nano and Magpie all need additional acoustic assets; sparse active parameters do not shrink Drama's stored experts. MLX/Metal/ONNX availability is a portability claim, not a pass on total bytes or memory.

## Practical next choices

| Need | Most relevant starting points | Remaining decision evidence |
| --- | --- | --- |
| Small default English reader | Kitten 0.8 nano/micro, Paradee 1.2, authentic Kokoro v1.0 int8 | Correct normalization/G2P, blinded listening, native adapter, complete M1 app onset/stop/memory/install measurements. |
| Small incremental speech with a native path | Pocket October 7M/18M, Phonon 31M | Exact model/state pins, voice terms, cancellation and boundary behavior, whole-app budgets. |
| Tiny multilingual/accessibility fallback | Selected Piper voices, eSpeak NG; Flite for a minimal fixed voice | Per-voice terms, GPL/distribution fit, language quality and native packaging. |
| Local emotional presets | NeuTTS-2E; Supertonic3 for documented expression/event cues | Current stock assets fail initial budget; no fitting complete replacement established. Different controls, not equivalent acting models. |
| Rich emotional controls with longer startup; larger storage/RAM still need an explicit decision | Qwen3 1.7B variants, CosyVoice3, VoxCPM2; Index2.5/Fish/Higgs only under appropriate terms | Runtime-specific controls, identity retention, pronunciation, actual Mac performance and complete licensing. |
| Joint dialogue production | Dia2, full VibeVoice, FireRedTTS2, MOSS-TTSD; Fish with its terms | Much larger resource envelope and release-specific streaming/voice behavior. |

For the newly permitted quality/latency tradeoff, prioritize listening and native feasibility checks of Qwen3-TTS 1.7B, CosyVoice3 and VoxCPM2 for explicit emotional control. Compare Sopro v2, Marvis and LuxTTS as reference-conditioned alternatives; Phonon 31M and Pocket remain smaller incremental options. This ordering is an engineering evaluation plan, not a measured quality ranking. No new benchmark or quality score was created for this catalog.

### Scope boundaries

VITS/VITS2, Tacotron2, FastSpeech2, Matcha-TTS and similar architectures remain useful training/inference baselines, but their many checkpoint licenses cannot be inferred from architecture names. Toolkits/runtimes such as Coqui TTS, ESPnet, NeMo, sherpa-onnx, MLX Audio and llama.cpp ports are not additional voice models. ASR models, speech-to-speech assistants, proprietary-only TTS APIs, and every derivative fine-tune are outside the 44-family count. The list is intended to make a concrete model/version/runtime/license selection possible without pretending to enumerate the entire internet.
